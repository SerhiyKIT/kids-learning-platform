# Kids Learning Platform — Дорожня карта та передача розробнику

> Документ для передачі проєкту іншому програмісту. Описує поточний стан,
> що вже зроблено, що залишилось, робочий процес і незмінні обмеження безпеки.
> Актуально станом на 2026-09-29 (HEAD `4743e3e`, merged PR #33).

---

## 1. Що це за продукт

Розвивальна веб-платформа для дітей **3–6 років**. Навчання у формі гри.

**Модулі:** безпека (ПДР, поводження з тваринами, небезпеки в місті/поза містом,
номери екстрених служб), математика, логіка, читання, письмо.

**Ролі:** дитина, батько/мати, вчитель, адміністратор.
- Вчитель створює групи й налаштовує уроки; ШІ допомагає генерувати контент,
  але **фінальне рішення (модерація) завжди за вчителем/адміном**.
- Батьки бачать історію всіх тестів/уроків своєї дитини.
- Діти обирають візуальний стиль; ШІ генерує оформлення під їхні вподобання
  **з обов'язковою модерацією**.

**Технічні пріоритети (у порядку важливості):**
1. Безпека і приватність дитячих даних.
2. Доступність і простота UX для дошкільнят (великі елементи, озвучка, мінімум тексту).
3. Кросплатформність (телефон / планшет / десктоп).
4. Продуктивність.

Продуктові й архітектурні документи — у теці [`/docs`](docs), починаючи з
`Технічний_фундамент.md`, `Обсяг_MVP.md`, `Ролі_та_приватність.md`,
`UX_гайд_дитячого_режиму.md`, `Формат_подання_уроків_та_ШІ.md`.

## 2. Стек і структура

- **Backend:** Java 21, Spring Boot 4.1, Maven, Flyway, PostgreSQL 16.
  Модульний моноліт, пакети `ua.kidlearn.*`. Єдина БД.
  - ⚠️ Boot 4.1 використовує **Jackson 3** — простір імен `tools.jackson.*`
    (не `com.fasterxml.jackson`).
- **Frontend:** Next.js 16 + TypeScript (App Router), PWA. Поки що — тільки
  кабінети дорослих + движок сцен на плейсхолдерах.
- **Сховище медіа:** MinIO (S3-сумісне) через AWS SDK v2.
- **Інфра (локально):** Docker Compose — PostgreSQL, MinIO, Mailpit (`/infra`).
- **CI:** GitHub Actions — два job'и: `backend-test` (postgres + JDK 21 +
  `./mvnw test`) та `frontend-build` (Node 22 + `npm ci` → lint → build).

Конвенції коду й процесу — у [`docs/CONVENTIONS.md`](docs/CONVENTIONS.md)
(з тегами `[CI]` / `[test]` / `[review]`, що позначають, чим правило контролюється).

## 3. Що вже зроблено (готове й перевірене CI)

**Backend — практично повний MVP:**
- Автентифікація на сесіях: `DelegatingPasswordEncoder` (bcrypt→argon2),
  CSRF (`CookieCsrfTokenRepository.withHttpOnlyFalse()`), верифікація email і
  скидання пароля (SHA-256 хеш одноразових токенів), rate limiting
  (fixed-window з інжектованим `Clock`).
- Приватність: доступ, обмежений власником, повертає **404, а не 403**;
  каскадне видалення на рівні БД (`ON DELETE CASCADE`) для «права бути забутим»;
  `audit_log` **ніколи не каскадиться** (actor `ON DELETE SET NULL`);
  жодного PII батьків у відповідях для вчителя/дитини.
- Навчальний цикл: модулі → уроки → версії → призначення (assignments) →
  спроби (attempts) → відповіді по сценах → результати для вчителя й батька.
- Контент-пайплайн: `LlmProvider` (stub) → `ScenarioValidator` (JSON Schema
  `lesson-scenario.schema.json` + бізнес-правила) → пакетний TTS (`TtsProvider`
  stub, кеш `AudioAsset` за `text_hash`, лінива ініціалізація бакета MinIO) →
  модерація (`auto_validated` → `approved` → `published`; `rejected_auto` —
  термінальний стан).
- «Хвіст» безпеки для адмінів: bootstrap першого адміна одноразовим
  env-токеном (`ADMIN_BOOTSTRAP_TOKEN`, порівняння constant-time, вікно
  самозакривається — 410); **обов'язкова 2FA (TOTP)** із секретом,
  зашифрованим AES-GCM (`TWOFA_ENC_KEY`), backup-коди, `TwoFactorGateFilter`.
- Guardrails: ArchUnit (структурні тести), тест `DevRoutesAbsentOutsideDevProfileTest`
  (доводить, що `@Profile("dev")` контролери відсутні поза профілем dev).
- Consents (пакет `consents`) — базовий облік згод.

**Frontend:**
- Каркас + кабінети батька/вчителя: реєстрація, логін, дашборд, діти, групи.
- Движок сцен (`PlaythroughEngine`, `SceneRenderer`, `ChoiceSceneView`,
  `SceneAsset`, `VoiceLinePlayer`) — працює на плейсхолдерах.
- Сторінка модерації (`/moderation`) — базова.
- Єдиний шар API `src/lib/api.ts` (`apiFetch`, credentials:include, echo
  XSRF-TOKEN, типізований `ApiError`); ESLint забороняє `localStorage`/
  `sessionStorage` і сирий `fetch` поза `api.ts`.

**Перевірений наскрізний сценарій для дорослих:** вчитель створює групу →
батько підключає дитину за кодом → призначає урок → дитина проходить →
результати видно і батьку, і вчителю.

## 4. Що залишилось — дорожня карта (= GitHub-задачі)

Розбито на 6 етапів (milestones). Кожен рядок нижче — окрема GitHub-задача,
яку створює скрипт `scripts/create-github-issues.sh`.

### M1 — Реальні AI-провайдери
- **Реальний LLM-провайдер** генерації уроків (замінити `StubLlmProvider`;
  промпт із `docs/Промпт_генерації_уроків.md`; ключ із env). *[high]*
- **Реальний TTS-провайдер** української озвучки (замінити `StubTtsProvider`;
  сліпий тест якості голосу). *[high]*

### M2 — Адмін та модерація (UI)
- **Екрани 2FA адміністратора** (setup з QR + backup-коди + verify). *[high]*
- **Кабінет модерації уроків** (перегляд / approve / reject / publish) —
  довести `/moderation` до повноти. *[high]*
- **Адмін-кабінет** (стан bootstrap, керування вчителями).

### M3 — Дитячий досвід
- **Полірування дитячого режиму** (voice-first, ≥64px елементи, landscape lock,
  таймер сесії ~15 хв, стікери) за `UX_гайд_дитячого_режиму.md`. *[high]*
- **Вибір візуального стилю дитиною + ШІ-генерація оформлення з модерацією** —
  ключова продуктова фіча.

### M4 — Навчальний контент
- **Ассети** згідно `Специфікація_ассетів.md` (пайплайн, реєстр, заміна
  плейсхолдерів).
- **Навчальні модулі:** математика, логіка, читання, письмо (типи сцен + seed-уроки).

### M5 — Production-готовність
- **Продакшн-деплой і hardening:** nginx/TLS, секрети лише через env, реальний
  SMTP, прибрати dev-ендпоінти (`seed-demo`, `register-role`). *[high]*
- **Provisioning вчителів адміністратором** (замінити dev-only `register-role`).
- **Повний батьківський кабінет:** історія + експорт/видалення даних
  (право бути забутим).

### M6 — Якість
- **E2E-тести** повного циклу (Playwright).
- **Аудит доступності та i18n** (українська) для обох режимів.

## 5. Робочий процес для нового розробника

1. **STEP 0 — синхронізація перед будь-якою роботою:**
   ```bash
   git checkout main && git pull --ff-only
   docker compose -f infra/docker-compose.yml up -d   # postgres, minio, mailpit
   ```
   Перед перевіркою «а чи працює без MinIO» — `docker compose stop minio`
   (CI не має MinIO; провайдери мусять працювати без нього).
2. Гілка на задачу: `feat/<short-name>` або `fix/<short-name>`.
3. **Локально запустити тести до пушу:** `cd backend && ./mvnw test`
   (CI ловив помилки, які локальний прогін би відсіяв).
4. **Зелений чекмарк GitHub Actions — єдиний авторитетний сигнал «готово».**
5. Виправляти корінь проблеми, **ніколи не маскувати**: без вимкнених тестів,
   без `eslint-disable`, без обходу валідації.
6. Слідувати `docs/CONVENTIONS.md`. Мова: пояснення/PR — українською;
   код, назви, коміти, коментарі — англійською.

## 6. Незмінні обмеження безпеки (діють у КОЖНІЙ задачі)

- **Жодних секретів у коді/репозиторії.** Усе через env: `ADMIN_BOOTSTRAP_TOKEN`,
  `TWOFA_ENC_KEY`, `DATASOURCE_*`, `SMTP_*`, `MINIO_*`, ключі LLM/TTS.
- **Жодних дефолтних облікових даних адміна.**
- **Приватність дитячих даних — понад усе:** 404-не-403 за власником;
  без PII батьків у відповідях для вчителя; каскадне видалення для «права бути
  забутим»; `audit_log` не каскадиться.
- **Dev-ендпоінти** (`seed-demo`, `register-role`) лишаються `@Profile("dev")`
  і мають бути прибрані/заблоковані перед продакшеном.
- **TOTP-секрети** зашифровані at rest (AES-GCM, `TWOFA_ENC_KEY`).
- **Зовнішні провайдери — за інтерфейсами**, зі stub/in-memory реалізаціями,
  щоб CI не потребував реальних API чи MinIO.
- ШІ-контент (уроки й дитячі стилі) — **завжди через модерацію** перед показом
  дитині.
